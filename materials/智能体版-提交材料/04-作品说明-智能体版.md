# 田诊卫士 · 智能体版 作品说明

比赛：“码上智农，电亮未来”智能体创新应用比赛
方向：智慧农业

## 一、作品定位

田诊卫士是面向小农户和基层农技人员的番茄病害诊断与安全用药智能体。用户可以用口语描述症状，也可以上传叶片照片；智能体先判断信息是否足够，再按需调用视觉诊断、病害检索、候选记录、规则校验和施药窗口工具，最后给出带来源、核验状态和待补信息的回答。

它解决的不是“识别出是什么病”就结束的问题，而是识别之后的连续决策：候选药剂是否登记在番茄上、防治对象是否匹配、剂量和单位是否合适、距采收是否满足安全间隔期、本季次数是否超限、天气窗口是否可用。这些判断不能只靠大模型“说”，必须由确定性规则逐条检查。

## 二、智能体设计

核心架构是“大模型规划 + 规则引擎否决”：

```text
用户口语/照片
      │
      ▼
大模型：理解 → 判断信息是否足够 → 选择工具 → 追问或组织回答
      │
      ├── get_leaf_diagnosis   视觉诊断结果
      ├── search_disease       口语症状 → 候选病害
      ├── get_candidate_records 候选药剂记录
      ├── validate_prescription 逐条规则校验
      ├── get_spray_window     按药剂计算模拟窗口
      ├── ask_user             信息不足时追问
      └── get_kb_status        知识库覆盖与核验状态
      │
      ▼
确定性规则引擎：身份、作物、对象、剂量、间隔期、次数
      │
      ▼
通过 / 待核验 / 拦截 + 来源 + 模拟窗口 + 安全边界
```

大模型负责理解、追问和规划，不直接生成农药名称、剂量或登记证号。所有用药条目必须来自知识库记录；`validate_prescription` 返回 `blocked` 的条目不得推荐，`needs_review` 的条目必须标注“待核验/需补充”。这样既保留了智能体的自然交互和自主规划，又避免了大模型幻觉进入农业安全决策。

## 三、一次完整交互

用户：“番茄叶子背面长白毛，茎上有黑斑，5 天后采收，能用什么药？”

1. 智能体判断没有照片，先说明视觉诊断不可用；调用 `search_disease`，得到晚疫病、灰霉病、早疫病等候选，检索分不是确诊概率。
2. 调用 `get_candidate_records`，读取番茄晚疫病的 5 条知识库记录。
3. 调用 `validate_prescription`，逐条检查。代森锰锌因安全间隔期 15 天、距采收仅 5 天被拦截；其余 4 条在剂量、作物、对象、间隔期上通过，但因来源未完成现行登记核验、本季用药次数未提供，标为“待核验/需补充”。
4. 调用 `get_spray_window`，按药剂给出未来模拟窗口，并明确“不是当地预报”。
5. 回答中给出结论、依据、待补信息和安全边界；前端同时展示工具调用轨迹、候选卡片、逐条校验结果和窗口卡片。

## 四、安全边界

- 程序在当前竞赛模式始终返回 `ready_for_field_use=false`，不签发正式田间处方。
- 知识库 40 条记录中，6 条为团队比对 GB/T 8321 标准，34 条为待核验种子资料；尚无具体产品登记证号。
- 天气为确定性模拟数据，施药窗口只用于演示时间约束。
- 视觉模型只覆盖番茄叶片四类；黄瓜、小麦仅支持文字问诊。
- 不涉及奖助学金、心理支持、医疗健康等敏感场景；不接入未经授权的校内业务数据。
- 实际用药以具体产品标签、现行登记信息和当地植保指导为准。

## 五、技术实现

| 模块 | 实现 |
|---|---|
| 视觉诊断 | MobileNetV3-Small（ImageNet 预训练）冻结骨干 + LogisticRegression 四分类；CPU 推理；纯色/模糊图片在推理前拒绝 |
| 症状检索 | jieba + BM25 + 字符 n-gram + 别名/口语症状加权；输出检索分，不解释为概率 |
| 规则校验 | 8 条确定性规则：来源与身份、禁用清单、限用范围、作物匹配、防治对象匹配、剂量与单位、间隔期与采收、每季次数 |
| 施药窗口 | 逐小时评估降雨、风速、温度、湿度；过滤已开始小时和超过最晚施药日的日期；WeatherProvider 可替换 |
| 智能体 | OpenAI 兼容 function calling；工具结果作为事实来源；未配置密钥时使用本地规划回退 |
| 前端 | 对话式页面：多轮消息、图片上传、工具调用轨迹、候选/校验/窗口卡片、移动端适配 |

## 七、创新点

1. **把大模型从“开药者”变成“规划者”**：模型负责理解、追问和工具编排，确定性规则负责否决。这样既有了智能体的自主性，又保留了农业场景需要的可审计性。
2. **工具链可回查**：每一次回答都能看到调用了哪些工具、用了哪条记录、哪条规则拦截、哪个来源未核验。
3. **对“不知道”的处理**：信息不足时追问，图文冲突时澄清，纯色/模糊图片拒识，未提供次数不当作 0。
4. **可离线演示**：没有 API Key 时使用同一组工具执行本地规划，评审环境也能复现；配置密钥后自动切换为大模型规划。
5. **安全边界前置**：`blocked` 不推荐、`needs_review` 必须标注、`ready_for_field_use` 始终为 false。

## 八、应用价值

目标用户是番茄种植者、家庭农场和基层农技人员。作品的直接价值不是替代农技人员，而是把“病名—药剂—依据—采收—次数—窗口”组织成可核对的清单，并把缺失信息和未核验环节暴露出来。后续可在真实登记核验、真实气象接入和小规模用户任务测试后，逐步扩展到更多作物和病害。

## 九、当前边界

本次未开展专家独立核验、真实用户访谈、田间试用、公网/微信真机/Docker 构建验收。上述事项未在材料中标记为已完成。作品的实验数字描述的是受控数据和固定功能契约下的表现，不是田间效果或农业处方合规保证。
