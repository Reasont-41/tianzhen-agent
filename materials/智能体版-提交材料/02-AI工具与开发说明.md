# AI 工具与开发说明

比赛：“码上智农，电亮未来”智能体创新应用比赛
作品：田诊卫士 · 智能体版
方向：智慧农业

## 一、作品形态与运行平台

| 项目 | 说明 |
|---|---|
| 作品形态 | 本地部署的 Web 智能体（FastAPI + 浏览器页面），同时提供表单版和对话版 |
| 运行环境 | Python 3.13.9（建议 3.12/3.13），CPU 推理，无需 GPU |
| 后端 | FastAPI、Uvicorn、Pydantic |
| 前端 | 原生 HTML/CSS/JavaScript，无外部前端框架 |
| 智能体入口 | `/agent` 对话页；`POST /api/agent/chat` |
| 表单入口 | `/`；`POST /api/consult` |
| 部署方式 | 本地 `uvicorn` 启动；GitHub 开源仓库提供部署说明和全部代码、知识库数据、模型权重 |

## 二、大模型与平台

| 项目 | 说明 |
|---|---|
| 默认平台/模型 | DeepSeek `deepseek-chat`，通过 OpenAI 兼容的 `/chat/completions` 接口调用 |
| 可替换平台 | 通义千问（DashScope）、智谱 GLM 等 OpenAI 兼容接口；通过环境变量 `TIANZHEN_LLM_BASE_URL`、`TIANZHEN_LLM_MODEL`、`TIANZHEN_LLM_API_KEY` 切换 |
| 调用方式 | Function calling / tool calling；模型自主决定调用哪个工具、是否追问、如何组织解释 |
| 模型职责 | 理解口语描述、决定工具调用顺序、在信息不足时追问、把工具结果组织成可读回答 |
| 模型不负责 | 不直接生成农药名称、剂量、间隔期、登记证号；所有用药条目必须来自知识库记录并通过规则引擎 |
| 密钥管理 | 只从环境变量读取；不写入代码、日志、响应或仓库；文档和截图中不出现密钥 |
| 离线回退 | 未配置密钥或接口失败时，使用本地规划器执行同一组工具；前端显示“本地规划模式” |

## 三、工具清单

智能体通过以下工具完成闭环：

1. `get_leaf_diagnosis`：读取本次会话叶片照片的视觉诊断结果。
2. `search_disease`：把口语症状检索为知识库候选病害。
3. `get_candidate_records`：读取某作物某病害的药剂登记记录。
4. `validate_prescription`：逐条检查身份、作物、防治对象、剂量、间隔期、每季次数等。
5. `get_spray_window`：按药剂计算未来施药窗口（模拟天气）。
6. `ask_user`：信息不足、图文冲突或候选接近时追问。
7. `get_kb_status`：读取知识库覆盖范围、核验状态和免责声明。

工具结果是事实来源；模型输出是解释层。校验结果为 `blocked` 的条目不会被推荐，`needs_review` 的条目必须标注“待核验/需补充”。

## 四、模型与算法

| 模块 | 模型/方法 | 说明 |
|---|---|---|
| 叶片分类 | MobileNetV3-Small（ImageNet 预训练）+ StandardScaler + LogisticRegression | 冻结骨干提取 576 维特征，CPU 训练与推理；番茄四类：晚疫病、早疫病、叶霉病、健康 |
| 拒识 | 验证集正确样本置信度第 5 百分位作为阈值 | 本次阈值 0.941003；测试集不参与阈值选择 |
| 症状检索 | jieba 分词 + BM25 + 字符 n-gram + 别名/口语症状加权 | 输出检索分，不解释为确诊概率 |
| 规则校验 | 确定性 Python 规则引擎 | 8 条规则：来源与身份、禁用清单、限用范围、作物匹配、防治对象匹配、剂量与单位、间隔期与采收、每季次数 |
| 施药窗口 | 逐小时规则评估 + 可替换 WeatherProvider | 当前为确定性模拟天气，始终标记 `is_simulated=true` |
| 图像质量门禁 | 尺寸、纹理、清晰度、纯色检查 | 纯色/严重模糊图片在推理前拒绝；不等同于通用非叶片检测 |

## 五、数据来源

| 数据 | 来源 | 使用方式与边界 |
|---|---|---|
| 叶片图像 | PlantVillage 公开数据集（Hughes & Salathé, 2015） | 5452 张原图，按 SHA-256 去重后 5438 张；训练/验证/测试 3262/1088/1088；原始图片不随包提供，保留样本清单和下载说明 |
| 农药标准 | GB/T 8321.9—2009、GB/T 8321.10—2018 | 团队比对 6 条记录；标准比对不等同于具体产品现行登记核验 |
| 药剂资料 | 公开农技资料整理 | 40 条记录，其中 34 条为待核验种子资料；尚无具体产品登记证号 |
| 登记信息适配器 | 中国农药信息网（ICAMA）公开页面 | 提供 `app/ingest/icama_adapter.py` 适配器；本次未完成全量现行登记核验 |
| 天气 | 确定性模拟源 | 仅用于演示时间约束；未接入真实气象 API |
| 规则参数 | 团队整理的经验规则 | 需在实际应用前由当地植保人员复核 |

## 六、AI 工具使用情况

| 环节 | 使用的 AI 工具 | 用途 | 人工把关 |
|---|---|---|---|
| 代码开发 | AI 编程助手（ZCode / Claude 等） | 代码重构、接口实现、测试用例草拟、文档草稿 | 开发者逐项审查、运行测试、修正逻辑 |
| 智能体规划 | DeepSeek `deepseek-chat` | 理解用户问题、选择工具、组织解释 | 规则引擎和知识库对输出做硬约束；`blocked` 不推荐 |
| 视觉模型 | MobileNetV3-Small（预训练权重） | 叶片特征提取 | 固定测试集评估；阈值由验证集确定 |
| 文档/PPT | AI 编程助手 + 办公软件 | 排版草稿、文字润色、结构建议 | 团队核对数据、来源和表述 |
| 海报/示意图 | AI 图像生成工具（如使用） | 封面/示意图素材 | 不用于实验图表；实验图表和页面截图均为实际产物 |

说明：

- AI 编程助手参与代码和文档草拟，但不替代开发者的技术判断；所有提交内容经过人工复核。
- 大模型不参与实验数据生成；准确率、拒识率、功能基准等数字来自实际训练和测试产物。
- 未使用 AI 生成虚构的专家评价、用户反馈、专利或软著材料。

## 七、数据与隐私

- 叶片照片只在本机视觉模型中处理，不上传给大模型；大模型只接收诊断结果文本、用户文字描述和工具返回的结构化结果。
- 不收集姓名、手机号、身份证号等个人敏感信息；会话只保存在服务进程内存中，默认 2 小时过期，不写入数据库。
- 不接入未经授权的校内业务数据；作品不涉及奖助学金、心理支持、医疗健康等敏感场景。
- API Key 只从环境变量读取，不进入代码仓库、日志或截图。

## 八、提示词与安全约束

系统提示词要求模型：

1. 信息不足时先调用 `ask_user`，不猜测。
2. 图片结果和检索分都不是确诊概率，必须如实说明。
3. 只能从 `get_candidate_records` 返回的记录中选药，禁止编造剂量、间隔期、登记证号。
4. 给出任何用药建议前必须调用 `validate_prescription`；`blocked` 不得推荐，`needs_review` 必须标注。
5. 施药窗口必须说明是模拟天气。
6. 未提供的字段写“未提供/需补充”，不得默认为 0。
7. 始终说明是竞赛演示，`ready_for_field_use=false`，不签发正式田间处方。

## 九、当前边界

- 知识库 40 条记录中 34 条待核验，6 条为标准比对；尚无具体产品登记证号。
- 未开展专家独立核验、真实用户访谈、田间试用、公网/微信真机/Docker 构建验收。
- 视觉模型只覆盖番茄叶片四类；黄瓜、小麦仅支持文字问诊。
- 天气为模拟数据；施药窗口只用于演示时间约束。
- 实际用药以具体产品标签、现行登记信息和当地植保指导为准。
